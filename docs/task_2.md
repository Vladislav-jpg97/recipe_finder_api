## Recipe Finder API — Pydantic схемы и валидация

---

## Контекст

Продолжаем **Recipe Finder API** из урока 1. Сейчас схемы живут прямо в `recipes.py` и не имеют валидаторов. На этом уроке выносим схемы в отдельный файл и добавляем полноценную валидацию входных данных.

---

## Часть 1 — Организация схем

Создай `app/schemas.py` и перенеси туда все Pydantic схемы. В роутере `recipes.py` импортируй их оттуда.

Проверь что все старые эндпоинты из урока 1 по-прежнему работают после переноса.

## Часть 2 — Обновляем существующие схемы

Добавь `model_config = ConfigDict(from_attributes=True)` в `RecipeBrief`. Пока это ничего не изменит в поведении — но в уроке 3 это понадобится когда вместо словарей будут ORM объекты.

---

## Часть 3 — Схема создания рецепта

Создай схему `RecipeCreate` для валидации входных данных при добавлении нового рецепта.

Требования к полям:

- `title` — строка, от 3 до 200 символов
- `slug` — строка, от 3 до 220 символов, только строчные буквы, цифры и дефисы
- `cuisine` — строка, от 2 до 50 символов
- `difficulty` — только `"easy"`, `"medium"` или `"hard"` (подумай какой инструмент Pydantic лучше подойдёт)
- `cooking_time` — целое число, от 1 до 600 минут
- `servings` — целое число, от 1 до 50
- `calories_per_serving` — целое число, не отрицательное
- `ingredients` — список строк, минимум 1 ингредиент, максимум 30
- `is_vegetarian` — булево, по умолчанию `False`
- `rating` — число с плавающей точкой, от 0.0 до 5.0, по умолчанию `0.0`

Используй `Field()` для constraints. Для `difficulty` подумай: `Literal` или `@field_validator` — что удобнее?

---

## Часть 4 — Валидаторы

Добавь в `RecipeCreate` следующие валидаторы:

### 4.1 Нормализация slug

Если slug содержит заглавные буквы — автоматически приводить к нижнему регистру. Если содержит пробелы — заменять на дефисы. Это должно происходить до валидации pattern.

Подсказка: `mode="before"` у `@field_validator`.

### 4.2 Валидация ингредиентов

Каждый ингредиент в списке должен быть непустой строкой длиной от 2 символов (после обрезки пробелов). Список должен возвращаться с обрезанными пробелами у каждого элемента.

---

## Часть 5 — Схема обновления рецепта

Создай схему `RecipeUpdate` — частичное обновление, все поля необязательны.

Какие поля можно обновлять: `title`, `cooking_time`, `servings`, `is_vegetarian`, `rating`. Применяй те же ограничения что и в `RecipeCreate`.

---

## Часть 6 — Новые эндпоинты

**6.1 Создание рецепта**

```text
POST /api/v1/recipes/
```

Принимает `RecipeCreate`. Добавляет рецепт в список `RECIPES` и возвращает `RecipeDetail` со статусом `201 Created`. Назначь `id` как максимальный существующий id плюс один.

**6.2 Обновление рецепта**

```text
PATCH /api/v1/recipes/{slug}
```

Принимает `RecipeUpdate`. Находит рецепт по `slug`, обновляет только те поля которые переданы (не `None`). Если рецепт не найден — 404. Возвращает обновлённый `RecipeDetail`.

Подсказка: у Pydantic модели есть метод который возвращает словарь только с непустыми полями — загляни в документацию `model_dump`.

## Часть 7 — Settings (бонус)

Добавь `app/config.py` с классом настроек через `pydantic-settings`:

- `app_name` — название приложения, по умолчанию `"Recipe Finder"`
- `debug` — режим отладки, по умолчанию `False`
- `default_page_size` — размер страницы по умолчанию, по умолчанию `10`
- `max_recipes` — максимум рецептов в хранилище, по умолчанию `1000`

Используй `app_name` в `FastAPI(title=...)`.

## Что проверит преподаватель

- `POST /api/v1/recipes/` с `difficulty: "unknown"` возвращает 422
- `POST /api/v1/recipes/` с `cooking_time: 0` возвращает 422
- `POST /api/v1/recipes/` с пустым списком `ingredients` возвращает 422
- `POST /api/v1/recipes/` с `slug: "My Recipe"` автоматически преобразует в `"my-recipe"`
- `PATCH /api/v1/recipes/несуществующий` возвращает 404
- `PATCH /api/v1/recipes/pasta-carbonara` с `{"cooking_time": 25}` меняет только `cooking_time`
- Все эндпоинты из урока 1 работают без изменений
